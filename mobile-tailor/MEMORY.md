# MEMORY — Sewzella Tailor (Partner) App (Expo)

## 1. What this app is
Native Android app for the **tailor / partner** role of Sewzella, converted 1:1 from the web partner module (`/partner/*`).
- Web frontend: `../frontend/` — pages in `frontend/src/modules/tailor`, layout `frontend/src/layouts/TailorLayout.jsx`, routes in `frontend/src/routes.jsx` (TAILOR / PARTNER MODULE).
- Backend: `../backend/` (Express). Flutter wrapper: none in repo.
- Built from the user app's foundation (`../mobile-user`): same primitives, style engine, native adapters, scripts.

## 3. Stack
Same as `../mobile-user/MEMORY.md` §3 (Expo SDK 58, RN 0.88, React 19.3, expo-router, zustand, axios, twrnc engine, lucide, socket.io-client). Added: `react-hook-form` (login + registration forms, same as web).

## 4. Folder structure and conventions
- `src/app/` routes only, generated by `scripts/gen-routes.py` (web path → screen + wrappers). `partner/(tabs)/` = the 5 bottom-nav roots kept mounted (Home, Orders, Wallet, Services, Profile).
- `src/screens/` one file per web page (same names as `modules/tailor/pages`). `src/components/tailor/` tailor components incl. `TailorLayout`, `TailorAuthLayout`, `ProtectedRoute`, `UIElements`, `GarmentForm`, `Registration/*`.
- `src/context/tailor/` AuthContext + NotificationContext (web TailorContextWrapper, mounted in `src/app/_layout.jsx`).
- Route wrappers (from web routes.jsx): `withTailorAuthLayout` (login/signup/forgot), `withTailorGuard(Screen, statuses)` (TailorProtectedRoute), `withTailorLayout` (TailorLayout header + bottom nav + pull-to-refresh).
- Add a screen: convert with `node scripts/web2rn.js <web file> <target>`, run `python3 scripts/fixups.py`, `node scripts/blockfix.js ../frontend/src src --write`, `python3 scripts/modalify.py <file>` for overlays, add the route to `scripts/gen-routes.py`, run it, then `node scripts/scan.js` + lint.

## 5. Auth
- `POST /auth/login` (password or OTP) → token + user; status from `/tailors/me` → APPROVED / PENDING_APPROVAL / REJECTED (`determineStatus`, same as web).
- Token in SecureStore key `tailor_token` (web localStorage `tailor_token`); `tailor_user`, `tailor_status` in AsyncStorage.
- 401 on an authenticated request → `session_expired` event → AuthContext clears the tailor session, disconnects the socket and opens `/partner/login` (web `services/api.js` interceptor).
- Guards: approved-only pages redirect pending/rejected tailors to `/partner/verification`; no token → `/partner/login`. Launch: approved → `/partner`, pending/rejected → `/partner/verification`, logged out → `/partner/welcome`.
- New tailors register with an SMS OTP and are inactive until an admin approves them (backend `isAutoActive`).

## 6. API layer
`src/lib/api.js` (shared with user app; the web's `modules/tailor/services/api.js` maps to it). Bearer `tailor_token`, 20 s timeout, GET de-dupe, FormData for uploads.

## 7. Web → native decisions (tailor-specific; shared ones in ../mobile-user/MEMORY.md §7)
- TailorLayout: mobile header (logo, status pill, bell + unread, avatar), orders sub-nav, bottom nav with pending-orders badge; desktop sidebar dropped. Pull-to-refresh re-mounts the page (web reloads the window). Bottom nav hides while the keyboard is open.
- Socket per tailor (`useSocketStore.connect(userId, 'tailor')`) and push registration happen in TailorLayout, as on the web.
- react-hook-form `{...register()}` → `{...field()}` from `src/lib/rnForm.js` (controlled TextInput, same rules/errors).
- Maps: `CustomerDropoffTracker` and the shop-location picker (`LocationPickerMap`) use react-native-maps; the browser Geocoder → `utils/reverseGeocode`. Tailor live tracker GPS → `lib/location.watchPosition`.
- New-order alert: web Web-Audio beep → vibration pattern (`utils/audio.js`); the web never actually played it (missing import) — native does.
- Socket "desktop notifications" (service worker) → local notification (expo-notifications).
- Inline SVGs → react-native-svg; `.dark-theme-uploader` CSS → `ImageUploader dark` prop; checkboxes → `components/ui/Checkbox`.
- Order detail slide-over → `FullScreenModal`; other overlays → `Dialog` / `Sheet`.
- Primitives: a `Btn` without a handler renders as a plain View so taps reach the card underneath (synced to the user app).

## 9. Commands
- Lint `npx expo lint` · scans `node scripts/scan.js` · bundle `npx expo export --platform android` · doctor `npx expo-doctor`.
- Release APK (local): `bash scripts/build-release.sh apk` (emulator APK: `ABIS=arm64-v8a,armeabi-v7a,x86_64 bash scripts/build-release.sh apk`) → `../releases/sewzella-tailor-v<version>-<code>.apk`, prints signing SHA-1/SHA-256.
- UI compare: as in `../mobile-user/MEMORY.md` §9 (`scripts/ui-compare/`, deep link scheme `sewzellatailor://`).

## 10. Known issues
- An approved tailor account was used for view-only testing on 2026-11-18; credentials are not stored. Order flows and form submissions remain untested (see CONVERSION_CHECKLIST.md).
- Registration needs a real SMS OTP (cannot be completed in automated tests).
- Push delivery and Google sign-in: as user app (Firebase SHA-1 for `com.sewzella.tailor` must be added for Google sign-in).

## 11. Assumptions
- versionCode 20 is higher than the Play build of 1.0.3; bump if Play rejects it.
- Launch for logged-out users is `/partner/welcome` (the web's partner landing page).
